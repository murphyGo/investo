# u155 — Business Logic Model

**Status**: Functional Design approved by “진행시켜”, 2026-09-09 KST.

## 책임 경계

수집·항목 선택·프롬프트 구성·분류 검증·본문 검증은 현재 소유자가 유지한다.
제공자 어댑터는 프롬프트를 받고 최종 텍스트와 제한된 실행 결과만 반환한다.
인증 보존은 운영 계층의 책임이며 LLM이 Secret 갱신 방법을 결정하지 않는다.
공통 설정/결과 타입은 중립 모듈에 두며 briefing이 publisher/notifier를
import하지 않는다. 공개 산출물에는 세션·계정 식별자를 추가하지 않는다.

## 실행 흐름

1. 입력 검증: 제공자 값, 날짜, 명시적 모델, 실행 모드와 인증 조건을 확인한다.
   제공자 미설정/공백은 기존 Claude 기본값; 그 외 알 수 없는 값은 오류다.
2. 실행 설정 고정: 한 실행의 모든 시장과 두 생성 단계는 동일 제공자를 쓴다.
   실행 도중 환경변수를 다시 읽어 제공자를 변경하지 않는다.
3. 인증 준비: 선택된 제공자의 인증만 준비한다. Codex 계정 로그인은
   자동화 전용 세션이며 유료 API 인증이나 대체 provider 설정을 거부한다.
4. 기존 자료 수집·신뢰 투영·후보 제한을 수행한다.
5. 시장별 분류와 본문 생성을 현재 재시도 정책 안에서 수행한다.
   동일 Codex 세션의 실제 CLI 호출은 실행 내부에서도 직렬화한다.
   응답은 기존 분류 JSON/본문 parser로 검증한다.
6. generation이 끝나면 Codex 인증 보존 checkpoint를 통과한다.
   새롭거나 갱신된 유효 세션을 보존하지 못하면 공개 발행으로 진행하지 않는다.
7. 기존 최종 문서·수치·면책·출처 검증과 usable-sibling 정책을 적용한다.
   검증을 통과한 공개 파일 목록만 기존 publisher로 전달한다.
8. 공개 저장소 push가 확인된 경우에만 기존 알림/Pages 정책을 적용한다.
9. 정상·부분·실패 종료 모두 종료 시 인증 보존과 정리를 시도한다.
   성공적인 발행 후 발생한 종료 실패는 과거 발행 사실을 지우지 않는다.

인증 복원 후 첫 CLI가 실행되기 전 실패하면 원본 Secret을 수정할
이유가 없다. CLI 실행 이후 실패하거나 timeout이면 유효한 최신 파일을
보존할 기회가 있어야 한다. 무조건 성공 상태나 빈 파일로 덮어쓰지 않는다.

## 인증 상태 전이

| 상태 | 허용 동작 | 다음 상태 |
|---|---|---|
| absent | 신뢰된 자동화 전용 로그인 파일로 초기 등록 | ready 또는 invalid |
| restored | 파일 형태·인증 방식 검증 | ready 또는 invalid |
| ready | 직렬화된 생성 호출 | ready, changed, generation_failed |
| changed | 갱신 파일 검증 후 Secret write | persisted 또는 persist_failed |
| generation_failed | 남아 있는 유효한 갱신 파일 보존 시도 | persisted 또는 recovery_required |
| persisted | 공개 발행 자격 검사 | ready_for_publication |
| invalid / persist_failed | 공개 발행 차단, 제한된 진단 | recovery_required |
| recovery_required | 스케줄 중지 및 재등록 | ready |

API에서 Secret의 평문을 다시 읽어 비교하지 않는다. 성공적인 암호화
write 응답과 다음 직렬 job의 로그인 확인이 보존 검증 근거다.

## 오류와 공개 결과의 구분

| 사건 | 생성·발행 처리 | 인증 처리 |
|---|---|---|
| Codex 인증 없음/다른 인증 방식 | 생성 전 실패 | 원본을 덮어쓰지 않음 |
| 알 수 없는 모델/모델 접근 불가 | 선택 오류 또는 생성 실패 | 자동 모델 변경 없음 |
| CLI nonzero/timeout | 기존 재시도 한도, 소진 후 해당 생성 실패 | 유효한 갱신 파일 보존 시도 |
| exit 0 + 빈/형식 오류 출력 | 기존 parser/retry가 실패 판정 | 성공 exit만으로 발행 승인하지 않음 |
| 토큰 갱신 성공 + 생성 실패 | 생성 실패 유지 | 갱신된 파일은 보존 |
| Secret 저장 실패 | 신규 공개 발행/알림 차단 | 제한된 재시도 후 재등록 필요 |
| 최종 문서 일부 차단 | 기존 유효 시장만 게시하는 partial 정책 | 정상 보존 |
| 공개 push 실패 | public notify/Pages 진입 금지 | 인증 보존 성공과 별도 기록 |
| 알림 실패 | 이미 완료한 게시 사실 유지 | 인증 상태와 별도 기록 |
| runner 강제 종료 | 공개 커밋 여부를 원격에서 재확인 | 보존 보장 없음; 복구 절차 |

## 두 저장소의 역할

비공개 저장소는 검토된 실행 코드 SHA와 workflow, 인증 상태를 관리한다.
공개 저장소의 최신 게시 이력은 별도 checkout으로 제공한다. 코드 SHA
고정과 최신 archive/carryover 조회는 별개이며, 고정한 오래된 checkout의
archive로 시황을 생성하지 않는다.

첫 구현은 원격 생성 서비스나 임의 사용자 요청 API를 만들지 않는다.
검토된 코드만 비공개 job에서 실행하고 발행 checkout에는 공개 결과만
반영한다. 기존 publisher의 명시적 파일 목록과 검증을 재사용한다.
비공개 checkout 전체·인증 디렉터리·실행 로그를 공개로 복사하지 않는다.
